# Button

There is no Kilowatt `Button` component. A button is Base UI's `Button` from `@base-ui/react/button` with a `ui-btn` class from `src/styles.css`. Use it in Base UI surfaces: toolbars, dialogs, menus, filter rows. Inside Material UI surfaces (the data components in `src/components/data`, such as `ErrorState` and `CursorPagination`), use Material's `Button`, which the theme bridge in `src/mui/theme.ts` styles with no ripple, no elevation and no uppercase text.

## Recipe

```tsx
import { Button } from '@base-ui/react/button';
import { MoreIcon, PlusIcon } from 'src/icons';

<Button className="ui-btn ui-btn-solid" onClick={save}>
  <PlusIcon />
  New work order
</Button>

<Button className="ui-icon-btn" aria-label="More actions">
  <MoreIcon />
</Button>
```

## Variants

- `ui-btn ui-btn-solid`: the primary action, filled with the primary color. One per view or dialog.
- `ui-btn` alone: the outlined secondary action. It rests on the sunken surface, lifts to the raised surface on hover and drops to the page surface on press.
- `ui-btn ui-btn-ghost`: low emphasis, transparent background and no border until hover, for toolbars, table rows and card headers.
- `ui-icon-btn`: a square, borderless icon-only button the size of a control (36px). Add `ui-icon-btn-sm` for the 28px card-control size.
- With an icon: put the icon from `src/icons` first, before the text. A leading icon trims the start padding by 2px.
- All `ui-btn` variants are 36px tall with the control radius and scale to 0.96 on press (unless reduced motion is on).

## Do and don't

Do:

- Name the action in the label ("Dispatch ticket", "Export CSV"), not "OK" or "Submit".
- While an action runs, keep `disabled`, add `focusableWhenDisabled` and `aria-busy`, and change the label to say what is happening (see Loading).
- Explain nearby why a disabled button is unavailable.

Don't:

- Don't put two `ui-btn-solid` buttons side by side.
- Don't pass colors or inline styles; the variant classes carry every state.
- Don't run a destructive or irreversible action straight from the button; confirm it in an alert dialog (see Primitives/Overlays).

## Accessibility

- Base UI renders a native `button`, handles keyboard activation, sets `data-disabled`, and with `focusableWhenDisabled` keeps the button in the tab order while disabled.
- Every `ui-btn` and `ui-icon-btn` shows a 2px secondary-color focus ring on keyboard focus.
- The caller must give an icon-only button an `aria-label`. Icons from `src/icons` are `aria-hidden`, so the label is the only accessible name.
