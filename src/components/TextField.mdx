# TextField

A text field lets people type a value. Kilowatt uses MUI's `TextField` from `@mui/material` (Material UI v9) with no wrapper; it bundles the label, the input, and helper text in one component. Props are MUI's: see the [TextField API](https://mui.com/material-ui/api/text-field/).

<Canvas of={TextFieldStories.Outlined} />

## When to use

- Use a text field for free text and numbers people type: titles, notes, IDs, setpoints.
- To pick one value from a short fixed list, use `Select`; from a long or searchable list, use `Autocomplete`.
- For on or off, use `Switch` or `Checkbox`; for a value on a range, consider `Slider` beside a text field.

## Usage

```tsx
import InputAdornment from '@mui/material/InputAdornment';
import TextField from '@mui/material/TextField';

<TextField label="Work Order Title" value={title} onChange={(event) => setTitle(event.target.value)} />

<TextField
  label="Peak Demand"
  type="number"
  slotProps={{ input: { endAdornment: <InputAdornment position="end">kW</InputAdornment> } }}
/>
```

## Variants

- `variant="outlined"` (MUI's default): use it everywhere.
- `variant="filled"` and `variant="standard"`: MUI's alternatives. Don't mix them with outlined fields in one form.

`size` is `small` or `medium` (the default); keep `medium` and set another size only for a one-off instance (Rules → Component size). `multiline` with `minRows` or `rows` makes a text area. Units and icons go in `InputAdornment`, passed through `slotProps.input`; attributes for the native input (`min`, `max`, `step`, `inputMode`) go in `slotProps.htmlInput`. In v9 the old `InputProps` and `inputProps` props are gone.

## States

- `required`: adds the asterisk to the label and the native `required` attribute.
- `error`: the value failed validation. Pair it with `helperText` that says how to fix it.
- `disabled`: the value can't be changed here. Say why nearby.

## Do and don't

- Do give every field a visible `label`.
- Don't use `placeholder` as the label; it disappears as soon as someone types. Use `label`, and `helperText` for an example value.
- Do put units in an end `InputAdornment`: "kW", "°F", "kWh".
- Don't write the unit into the label and leave the field bare; the adornment keeps the unit beside the number.
- Do write error text that says how to fix the value.
- Don't set `error` without `helperText`; a red outline alone doesn't say what's wrong.
- Do use the outlined variant throughout a form.
- Don't restyle the outline with `sx` or `borderColor`; the field takes its border and focus outline from the theme.
- Do let the field take the theme radius.
- Don't give one field its own `borderRadius`; the radius changes only through `shape-radius`.

## MUI departures

- `medium-size`: leave `size` at `medium`, the default; set `small` or `large` only for a one-off instance.
- `control-outlines`: the resting outline is `palette.control.border`, shared by every input, select, outlined button and toggle button, from the Figma button-border tokens: slate 500 in light, navy 700 in dark, quieter than 3:1 by design. Hover is navy 200 (light) or navy 300 (dark); focus keeps MUI's 2px primary outline. Error and disabled keep MUI's colors.

Theme-wide departures (CSS variables, the 8px corner radius, surface and border levels, the navy primary for the focus ring and label, and the other intent colors) apply too; see Foundations → MUI departures.

## Accessibility

- MUI ties the `label` and `helperText` to the input with `for` and `aria-describedby`, so screen readers read both.
- A field without a visible label needs an `aria-label` through `slotProps.htmlInput`; prefer a visible label.
- `error` sets `aria-invalid`. Announce form-level errors, such as a failed save, separately.

## Related

- `Select` and `Autocomplete` for choosing from a list.
- `Slider` for a value on a range.
