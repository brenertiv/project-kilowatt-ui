# DataTable

## When to use

- Rows of records that people compare across several columns: meters, buildings, bills, equipment.
- Lists that need sorting, search, a filter, paging, column controls, selection or CSV export.
- Small sets loaded in one request (client mode) and portfolio-scale data paged by the server (server mode).

## When not to use

- A short list of records with a primary line, a secondary line and something on the right: use `EntityList` from `src/components/data`. See [EntityList](?path=/docs/data-entitylist--docs).
- A cursor-paged API list with no total count: the server mode pager needs a total. Use `EntityList` with `FilterBar` and `CursorPagination`, as in [the list page pattern](?path=/docs/patterns-listpage--docs).
- One headline number: use `StatCard`.
- A trend over time: use a chart. A `SparklineCell` only shows the shape of a series inside a row.
- Layout. A table is for data, never for arranging content on a page.

## Columns

Define columns with `defineColumns` from `src/components/columns`. Each `ColumnSpec` names a row field, a header and a `type`, and gets the right cell, alignment, sort function and CSV value:

```tsx
import { defineColumns } from 'src/components/columns';
import { DataTable } from 'src/components/DataTable';
import type { Meter } from 'src/meters';

// Define columns once, outside the component, so they stay referentially stable.
const columns = defineColumns<Meter>([
  { id: 'name', header: 'Meter', type: 'text', pin: 'left' },
  { id: 'source', header: 'Source', type: 'chip' },
  { id: 'energyStarLink', header: 'Energy Star', type: 'status', tone: (value) => (value === 'Linked' ? 'positive' : 'neutral') },
  { id: 'linkStartDate', header: 'Link start', type: 'date' },
  { id: 'channels', header: 'Channels', type: 'numeric' },
]);

<DataTable data={meters} columns={columns} label="Meters" noun="meters" getRowId={(meter) => meter.id} />;
```

The types map to cells: `numeric`, `percent` and `currency` use `NumericCell`, `delta` uses `DeltaCell`, `date` uses `DateCell`, `status` uses `StatusCell`, `chip` uses `ChipCell` and `text` prints the value. Numeric types and `delta` align end with tabular digits. A `delta` column takes `unit` and `upIsGood` (set it false for consumption and cost).

For anything a spec cannot express, write the column with `createColumnHelper<DataTableFeatures, Row>()` and add it to the list: a `LinkCell` on the name, an `ActionsCell` in a trailing column pinned right, a `SparklineCell`, or a column that the toolbar filter narrows (it needs `filterFn: 'equalsString'`). Column `meta` takes `align`, `pin`, `order` and `exportValue`.

Empty values (`null`, `undefined` or an empty string) render an em dash with the accessible name "None". Don't render your own placeholder.

## Client and server mode

**Client mode** (the default) takes every row in `data` and sorts, searches, filters and pages in the browser. Use it for sets that load in one request. Add `virtualize` with an "All rows" page size (`0` in `pageSizes`) for thousands of rows.

**Server mode** (`mode="server"`) takes one page of rows. The table reports sorting, search, filters and paging through `onStateChange` (or writes them to the URL with `syncToUrl`); the caller fetches that page and passes `server.rowCount` (the total across pages) and `server.isFetching`. Keep previous rows while the next page loads so the table dims them instead of flashing a skeleton. See the `ServerSide` story.

State can be controlled per slice with `state`. Any slice you omit is managed inside the table. With `syncToUrl`, the URL is the source of truth and `state` only seeds the defaults.

Sort, search and filter changes return to the first page.

## Do and don't

- **Do** set `getRowId` to a stable id. Selection, expansion and React keys use it.
- **Do** keep `data` and `columns` referentially stable: define columns outside the component or memoize them.
- **Do** name what is searched when you set `searchColumns`. The search box is named "Search {noun}" by default; pass `searchLabel` to change that and `searchPlaceholder` for a hint such as "Name or id".
- **Do** set `tableId` on tables people return to, so their column layout and density persist.
- **Do** pass `isLoading` for the first load and `error` with `onRetry` for a failed request. Don't hand-roll a spinner or an error block.
- **Don't** pass `numericColumns` for new tables. Put `meta.align: 'end'` on the column, or use a numeric `ColumnSpec` type.
- **Don't** invent a total. In server mode, `server.rowCount` must come from the API.
- **Don't** pick a status tone by color. Choose it from what the state means.

## Accessibility

- `label` is the table's accessible name. The footer count ("1–10 of 42 meters", plus the selected count) is a live status region that describes the table.
- Sortable headers are buttons and expose `aria-sort`.
- Column resize handles are buttons: Left and Right arrows resize by 16 pixels, double-click resets.
- Selection checkboxes, the expand toggle, the pager buttons, the density toggle, the selects and the search box all carry accessible names. The search box's name is hidden label text, not its placeholder.
- An empty body says "No {noun} match these filters." only while a search or filter is applied; otherwise "No {noun} to show."
- Every string the table renders comes from `src/i18n/en.json` under `table.*`.
- While a server page loads the table is marked `aria-busy`. Virtualized tables set `aria-rowcount` to the full row count.
- The loading skeleton is a status region and the error state is an alert.

## Composition

- [Cells](?path=/docs/table-cells--docs): `StatusCell`, `ChipCell`, `NumericCell`, `DeltaCell`, `DateCell`, `LinkCell`, `ActionsCell`, `SparklineCell` and `EmptyCell`, from `src/components/cells`.
- [Table states](?path=/docs/table-states--docs): `TableSkeleton`, `TableError` and `TableEmptyRow`. DataTable renders them for `isLoading`, `error` and no rows; use them directly only in a hand-built table.
- [FilterBar](?path=/docs/data-filterbar--docs) and [CursorPagination](?path=/docs/data-cursorpagination--docs) work over the API's cursor-paged list params, not DataTable state. DataTable has its own toolbar (search, filter, columns, density, export) and pager. Use FilterBar and CursorPagination with `EntityList` for cursor-paged lists.
- Row actions: an `ActionsCell` column for one row, `bulkActions` with `selectable` for several.
