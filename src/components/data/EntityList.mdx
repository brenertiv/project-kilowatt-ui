# EntityList

## When to use

- A short list of records where each row has a name, a second line and one thing on the right: recent alerts, a building's meters, open work orders in a card.
- A list page with search and cursor paging, together with [FilterBar](?path=/docs/data-filterbar--docs) and `CursorPagination`.
- A master list beside a detail panel: rows with `onClick` and `selected`.

## When not to use

- When readers compare several fields across records, sort by column or export: use [DataTable](?path=/docs/table-datatable--docs).
- One record: use [EntityCard](?path=/docs/data-entitycard--docs).
- A list of links that are not records, such as navigation: use the app's navigation.

## Do and don't

Do:

- Render `primary` with `EntityName` so placeholder names are replaced and explained.
- Put a [StatusChip](?path=/docs/data-statuschip--docs) or a value in `trailing`; it wraps under the text on narrow screens.
- Pass `state` from `fromQuery` and `empty` copy that names what is missing.
- Match `skeletonRows` to the page size so the layout does not jump.
- Use `to` for rows that open a page and `onClick` for rows that select something in place.

Don't:

- Don't wrap the list in `DataState`; pass `state` instead.
- Don't set both `to` and `onClick` on a row. `to` wins and `onClick` is ignored.
- Don't invent a total count. Under the list, `CursorPagination` says what is on the page.
- Don't put buttons inside a row that is itself a link or a button.

## Accessibility

- The list is a list of list items; linked rows are links and clicked rows are buttons, each with a visible focus ring.
- `selected` highlights the row visually; say what is selected in the detail panel too.
- Set `aria-label` when there is no visible heading tied to the list, e.g. "Open alerts".
- Loading, empty and error are announced through the same regions as [DataState](?path=/docs/data-datastate--docs).

## Composition

- Built on [DataState](?path=/docs/data-datastate--docs) with a `ListSkeleton`.
- Above it, [FilterBar](?path=/docs/data-filterbar--docs); below it, `CursorPagination`; above both, a [PageHeader](?path=/docs/data-pageheader--docs).
- Rows hold `EntityName`, `RelationLink`, `DateText` and [StatusChip](?path=/docs/data-statuschip--docs).
- The Patterns/ListPage story shows the whole list page wired to the mock API.
