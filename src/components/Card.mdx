# Card

A card holds content and actions about one subject. Kilowatt uses MUI's `Card`, `CardHeader`, `CardContent`, `CardActions` and `CardActionArea` from `@mui/material` (Material UI v9) with no wrapper; the theme differs from stock MUI only as listed under MUI departures below. Props are MUI's: see the [Card API](https://mui.com/material-ui/api/card/), [CardHeader API](https://mui.com/material-ui/api/card-header/), [CardContent API](https://mui.com/material-ui/api/card-content/), [CardActions API](https://mui.com/material-ui/api/card-actions/) and [CardActionArea API](https://mui.com/material-ui/api/card-action-area/).

## When to use

- Use a card for one self-contained subject that sits beside others like it: a building in a portfolio, a meter, a saved report.
- Use an outlined card with a headline number for a metric: the figure at the card's foot, set by `SourceFigure` or `PlainFigure` (Metric, below).
- Use a highlight card for the one card a page leads with: the same outlined card, with its title a step above the others and a More menu (Highlight, below).
- Use an outlined card for every chart: a title-only `CardHeader` names what's measured, and the chart sits straight in the card, padding itself 16px, with its unit above the value axis (Rules → Charts).
- For a plain raised area with no card structure (a panel, a toolbar backdrop), use `Paper`.
- For rows of the same fields that people compare or sort, use a table, not a grid of cards.
- For content that people expand and collapse in place, use `Accordion`.

## Usage

```tsx
import Button from '@mui/material/Button';
import Card from '@mui/material/Card';
import CardActions from '@mui/material/CardActions';
import CardContent from '@mui/material/CardContent';
import Typography from '@mui/material/Typography';

<Card>
  <CardContent>
    <Typography variant="overline" sx={{ color: 'text.secondary' }}>
      Building
    </Typography>
    <Typography variant="h5" component="h2">
      350 Fifth Avenue
    </Typography>
  </CardContent>
  <CardActions>
    <Button>View Building</Button>
  </CardActions>
</Card>
```

For a chart, use `variant="outlined"`, put the title in `CardHeader`, with any actions in its `action` slot, and the chart straight in the `Card`, with no `CardContent`, run through `useChart` from `src/charts` so it takes Kilowatt's chart theme. The chart pads itself 16px at the sides and bottom (`px: 2, pb: 2`), in line with the title and `CardContent`; the reference charts do this for you, and their `inset` changes it. Wrap the chart in a `figure` named by a one-line summary of what it shows (`aria-label`). The summary isn't shown; it's the chart's text alternative for screen readers:

```tsx
import CardHeader from '@mui/material/CardHeader';
import { TruncatedText } from 'src/components/TruncatedText';
import { useChart } from 'src/charts/useChart';

function EnergyUseChart() {
  const ref = useChart(buildEnergyChart); // a stable function that adds the amCharts chart to the root
  return <Box ref={ref} sx={{ height: 240 }} />;
}

<Card variant="outlined">
  <CardHeader
    title={<TruncatedText>Energy Use</TruncatedText>}
    action={<IconButton aria-label="Chart options">…</IconButton>}
  />
  <Box component="figure" aria-label="This period used 32,914 kWh, 6% less than the previous 30 days." sx={{ m: 0, px: 2, pb: 2 }}>
    <EnergyUseChart />
  </Box>
</Card>
```

### Header layout

- **A title, no subtitle.** The title says what's measured: "Energy Use", not "Energy Use (kWh)". The page sets the period for every card, so headers don't repeat it.
- **Units sit with the numbers.** "32,914 kWh" in the content, a unit above a chart's value axis, a unit after each value in a tooltip or list. A card can show values in more than one unit, and each number carries its own.
- **A subtitle is the exception.** Add one only when the card's period differs from the page's ("Last 12 months" on a monthly dashboard). It holds that period and nothing else, never a unit.
- **Titles sit in one place.** A header's title is 16px from the card's top and left edges, with or without a subtitle, so the titles in a grid of cards line up. A subtitle only adds height below the title.
- **One line each.** Titles and subtitles truncate instead of wrapping (`card-header-layout`). Wrap each in `TruncatedText`, so a cut-off title shows in full in a tooltip.
- **The action lines up with the content.** An icon button in `action` is centered on a one-line title, and its icon sits 16px from the card's right edge, in line with the content below. The button's hover background reaches to 8px from the corner, which is why cards round at 16px (`card-radius`). The button doesn't add height: a header with only a title is the title line plus 16px above and below.

### Metric

A metric card leads with one headline number. Set it with `SourceFigure`, `ExplainedFigure` or `PlainFigure` from `src/components/SourceFigure`, which share one type; see [Data display → SourceFigure](?path=/docs/data-display-sourcefigure--docs).

- **The figure is `h2` with tabular numerals.** The unit follows it in `body1` and `text.secondary`, and the value is formatted with `Intl.NumberFormat`. A value that's a phrase rather than a number (longer than 14 characters, such as “4 on track, 2 at risk”) steps down to `h4`, so it still fits.
- **The figure sits at the card's foot, with a 160px floor.** Give the card `minHeight: (theme) => theme.spacing(20)` (20 spacing units) as a flex column, and its `CardContent` `mt: 'auto'`, so single-figure cards in a row hold one height and their figures line up along the bottom.
- **The metric sits above any chart.** When a card has both, the figure comes first, in `CardContent`, and the chart follows, straight in the card.
- **No caption under the figure.** A figure that needs clarifying opens its explanation instead: `SourceFigure` opens a dialog with where it comes from, with what would have been the caption as its `note`, and `ExplainedFigure` opens one with a note alone. A figure with nothing to explain is a `PlainFigure`, not a control.

```tsx
import { SourceFigure } from 'src/components/SourceFigure';

<Card variant="outlined" sx={{ minHeight: (theme) => theme.spacing(20), display: 'flex', flexDirection: 'column' }}>
  <CardHeader title={<TruncatedText>Energy Use</TruncatedText>} action={options} />
  <CardContent sx={{ pt: 0, mt: 'auto', display: 'flex', flexDirection: 'column' }}>
    <SourceFigure title="Energy Use" value="32,914" unit="kWh" note="6% less than the previous 30 days." source={source} />
  </CardContent>
</Card>
```

### Highlight

The highlight card is the card a page leads with, such as the selected view's card at the top of a dashboard. It's not a component of its own: it's an outlined `Card` with the same surface and border as every other card, so it leads by its place and its title, not by color.

- **The title is a step above other card titles.** Card titles are `h6` (`card-header-title`); the highlight's is `h5`, through the header's title slot: `slotProps={{ title: { variant: 'h5', component: 'h2' } }}`. It's the page's lead heading, so it renders as an `h2`.
- **A More menu in the top right.** An icon button with `more_horiz` in the header's `action`, placed as every card header's action is (`card-header-layout`), opening a `Menu` of the card's actions.
- **Its content follows the other card rules.** A metric at the top, then a chart straight in the card, each with its own inset.

### Padding

The `Card` has no padding of its own. Each kind of content owns its inset, so a chart, a list and a block of text can each take the padding that suits it:

| Content | Inset | How |
| --- | --- | --- |
| Header | 16px | `CardHeader`, always. |
| Text, a metric, a form | 16px | `CardContent`, always 16px. Under a `CardHeader`, take its top padding off (`sx={{ pt: 0 }}`) so the gap below the header stays 16px. |
| A chart | 16px at the sides and bottom by default | Straight in the `Card`, no `CardContent`. The reference charts pad themselves through `inset`: `2` (16px) in line with the title and `CardContent`, `1` (8px) for a tighter fit, `0` to run edge to edge. |
| A list or table | Its rows' own padding | Straight in the `Card`, no `CardContent`. |

**Don't resize `CardContent`.** MUI pads the last `CardContent` in a card with a stronger rule (`:last-child`), which our `card-content-padding` departure sets to 16px. A plain `sx={{ pb: 1 }}` loses to it, so the bottom padding wouldn't change. Content that needs a different inset leaves `CardContent` out and sets its own padding.

## Variants

- `variant="elevation"` (MUI's default): the card sits on surface level2 with MUI's elevation 1 shadow. Use it for cards on the page background.
- `variant="outlined"`: a border (`divider`) instead of a shadow. Use it for cards in a dense grid, on a surface that already has depth, and for every chart card.

`CardHeader` sets a title, a `subheader` and an `action` (an icon button or menu) in one row. `CardContent` pads the content, and `CardActions` lays out text buttons along the bottom. `CardActionArea` turns the whole card into one button, for a card that only opens its subject.

## Do and don't

- Do keep one subject per card, with a heading that names it.
- Don't pack unrelated content into one card; split it into cards or sections.
- Do put a card's actions in `CardActions` as text buttons, named for what they do.
- Don't put a contained button on every card in a grid; the repeated emphasis competes with the view's main action.
- Do use `CardActionArea` when the whole card is one action, such as opening the building.
- Don't put buttons or links inside a `CardActionArea`; a button can't contain another control, so use `CardActions` for a card with several actions.
- Do choose one look per grid: all elevation or all outlined.
- Don't add a border to an elevation card or a shadow to an outlined one; keep one edge per card.
- Do make a chart card outlined, with a title-only `CardHeader` that says what's measured.
- Do set a metric card's figure with `SourceFigure` or `PlainFigure`, at the card's foot over a 160px floor, and above any chart.
- Don't put a caption under a headline number; put it in the figure's `note`, so it opens with the figure's source.
- Do lead a page with at most one highlight card, an outlined card with an `h5` title and a More menu.
- Don't give a highlight card its own surface, border or color; it differs only by its title and its place.
- Do put each unit next to its number: `32,914 kWh`, formatted with `Intl.NumberFormat` and a no-break space.
- Don't put units or the page's period in a title or subtitle; use a subtitle only for a period that differs from the page's.
- Don't set a chart's colors in chart code; `useChart` applies the chart theme, and series take `chart.series` in order.
- Do let each kind of content set its own inset: `CardContent` for 16px, a chart's `inset`, a list's own rows.
- Don't change `CardContent`'s padding with `sx`; its last-child bottom padding won't move. Leave `CardContent` out instead.
- Don't pad the `Card` itself, or nudge a header action into place with margins; its position comes from `card-header-layout`.
- Do wrap header titles and subtitles in `TruncatedText`, and keep them short enough to fit a typical card.
- Don't let a title wrap or set `noWrap` on it yourself; the theme keeps it on one line, and `TruncatedText` shows the rest.
- Do let the card take its surface and its 16px radius from the theme.
- Don't set the card's `backgroundColor` or `borderRadius` with `sx`; the surface comes from its elevation and the radius from `card-radius`.

## MUI departures

- `card-header-title`: `CardHeader` titles use `h6` (16px) instead of MUI's `h5` (18px), so a page of cards reads by its content; a Highlight card sets its title a step above, in `h5`.
- `card-header-subheader`: `CardHeader` subtitles use `body2` (14px) instead of MUI's `body1` (16px), so the 16px title leads. It's the size MUI uses when the header has an avatar.
- `card-header-layout`: a `CardHeader` action is pulled out 8px at the top, right and bottom instead of MUI's 4px and 8px, so its icon sits level with a one-line title and 16px from the right edge; contents align to the top instead of the center, so a title keeps its place with or without a subtitle; titles and subtitles stay on one line and truncate.
- `card-content-padding`: `CardContent` is 16px on every side instead of 24px at the bottom of the last one.
- `card-radius`: cards round at twice the theme radius, 16px instead of MUI's one radius, because their header action and `CardActions` buttons sit 8px from the corners.
- `paper-surface-levels`: a card, outlined or raised, sits on surface `background.level2` in both schemes, a step above the level1 frame it's laid out on, in place of MUI's white light surface and its dark-scheme white overlay.
- `focus-ring`: keyboard focus is a 2px ring in `palette.control.focus`, the brand blue (brand 700 in light, brand 200 in dark), 2px outside the control, instead of MUI's background tint alone. A clickable card's `CardActionArea` shows it.

How the charts inside cards differ from stock amCharts (an outlined card, the 16px inset, units above axes) is listed on each chart's page and in Foundations → amCharts departures. Theme-wide departures (CSS variables, the theme radius, surface and border levels, the text and intent colors) apply too; see Foundations → MUI departures.

## Accessibility

- `Card` renders a plain `div` with no role; give it a heading (`component="h2"` or the right level for the page) so people can find it by heading.
- `CardActionArea` renders a `button`, with keyboard activation and a visible focus state. Its accessible name is all the text inside it, so keep that text short.
- Name each button in `CardActions` for its action, so "View Building" makes sense when read out of the card.
- A chart draws on a canvas that screen readers can't read. Put it in a `figure` named by a one-line summary with the numbers that matter (`aria-label`); the summary isn't shown on screen. For detailed data, offer it as a table too. Don't give the chart's container `role="img"`: amCharts adds focusable elements for keyboard access, and an image can't contain them.
