# Field

There is no Kilowatt `Field` component. A text field is MUI's `TextField` from `@mui/material`, used as MUI documents it and themed as stock MUI. `TextField` wires the label, helper text and error state to the input, so you never write `id` or `htmlFor` by hand.

<Canvas of={FieldStories.Default} />

## Usage

```tsx
import TextField from '@mui/material/TextField';

<TextField
  label="Site name"
  value={site}
  onChange={(event) => setSite(event.target.value)}
  required
  error={!site}
  helperText={site ? 'Used on tickets and meter rollups.' : 'Site name is required.'}
/>
```

## States

- Helper text: `helperText` under the input, for anything the label alone does not explain.
- Error: set `error` and put the fix in `helperText` in place of the help text.
- Disabled: set `disabled`, and say in `helperText` who can change the value.
- Required: set `required`; MUI adds the asterisk to the label and `required` to the input.

## When to use something else

- A number with limits, a pick from a list, search as you type, a range or a few options: see Primitives/Forms.
- A long free-text note: `TextField` with `multiline` and `minRows`.

## Kilowatt rules

- Use MUI's default `outlined` variant; don't mix in `filled` or `standard`.
- Don't pass colors or style the input; use `sx` only for layout, such as width.
- Labels and messages are sentence case.

## Do and don't

Do:

- Always pass a visible `label`.
- Write the error as the fix ("Site name is required."), not a code.

Don't:

- Don't use a placeholder as the label.
- Don't build a label and input by hand when `TextField` does the wiring.

## Accessibility

- `TextField` links the label to the input and the helper text to it as its description, and sets `aria-invalid` when `error` is set.
- The caller supplies the label text and an error message that says how to fix the value.
