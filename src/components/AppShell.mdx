# AppShell

`AppShell` is the frame around every Enertiv page. It's Kilowatt's own component, composed from MUI's `List`, `ListItemButton`, `Drawer`, `Dialog`, `Paper`, `Menu`, `Slide`, `AppBar`, `IconButton`, `TextField`, `ToggleButtonGroup`, `Badge`, `Tooltip` and `Avatar` (`@mui/material`, Material UI v9; MUI documents their props). MUI has no app frame of its own, so the shell is where the layout rules for one live.

On wide screens (`md` and up), from left to right:

- **Rail.** The company button at the top (the company's mark, or its initials without one), which opens the company menu; one icon per section; then, at the bottom, Search and the sections placed at the `end`: Notifications and My account. It sits on the page surface, outside the frame.
- **Section panel.** The current section's title with its header buttons (a filter when the panel has one, the panel's `headerAction`, and Collapse navigation), optional actions (a New button) and its pages. It resizes from its edge (220px to 380px) and undocks from its header. Undocked, resting on a section in the rail floats that section's panel over the page, so another section's pages are one move away; Dock navigation, in the header or the floating panel, docks it again. Sections with no pages of their own have no panel.
- **Header.** The scope (`headerStart`) at the start and page-wide actions (`headerEnd`) at the end, nothing else, so the scope has the room. It has no line under it, and the page's 24px gutter on its sides and top, so the scope sits in line with the page's title. `hideHeader` leaves it out, for a page with no scope and no page-wide actions.
- **Main.** The page, padded 24px. The frame fills the window and only `main` scrolls. A `PageHeader` in the page pins there.
- **Aside.** An optional column at the end, for the assistant, whose left edge resizes it (280px to 560px). `asideDocked={false}` floats it over the page instead, and its header drags it. It's beside the page wherever the rail shows; the bottom sheet is the phone shell's alone.
- **Search.** One search dialog for the whole app, opened from Search in the rail's foot, above Notifications, on every page. On phones it's in the menu's header, beside Close, and fills the screen. It finds a page in any section by name and goes to it.

Below `md` the shell switches to a layout built for a phone's browser: a sticky header and a one-column menu (Variants → Phones).

## When to use

- Use it once, at the root of the app, around every page.
- Use the panel for a section's own pages. For actions on the current page, use the page's header or toolbar, not the panel.
- For the scope (the portfolio or property), use `headerStart`; for page-wide actions, `headerEnd`.
- For details of one item, open a `Drawer` from the page rather than the aside; the aside is for a tool that stays open across pages, like the assistant.

## Usage

```tsx
import { AppShell } from 'src/components/AppShell';

<AppShell
  company={{ id: 'ridgeline', name: 'Ridgeline Logistics REIT' }}
  companies={companies}
  onCompanyChange={(company) => switchCompany(company)}
  sections={[
    {
      id: 'workspace',
      label: 'Workspace',
      icon: 'table_rows',
      panel: { items: [{ id: 'reporting-readiness', label: 'Reporting readiness', secondary: 'Dashboard', icon: 'table_rows' }] },
    },
    { id: 'maintenance', label: 'Maintenance', icon: 'tune', hideOnPhone: true },
    {
      id: 'account',
      label: 'My account',
      initials: 'MC',
      placement: 'end',
      panel: { colorScheme: true, items: [{ id: 'profile', label: 'Profile', icon: 'devices' }] },
    },
  ]}
  section="workspace"
  page="reporting-readiness"
  onSectionChange={(section) => navigate(`/${section}`)}
  onPageChange={(page, section) => navigate(`/${section}/${page}`)}
>
  <Page />
</AppShell>
```

Each section carries its own `panel`, so the undocked panel and the phone menu can show any section's pages. The shell holds no routes. It reports choices through `onSectionChange` and `onPageChange` (which names the page's section, since it can be chosen from another section's panel), and an item with an `href` renders as a link, so the app's router decides what happens. The panel's open state and width start from `defaultPanelOpen` and `defaultPanelWidth`; `onPanelOpenChange` and `onPanelWidthChange` let the app remember them.

On phones, add `viewport-fit=cover` to the app's viewport meta tag, so the shell's safe-area padding takes effect (Variants → Phones).

### Columns by the page's width

MUI's `Grid` reads the window, and the docked panel and aside don't change the window, so a page beside them can be left a fraction of what its breakpoints think it has. `AppShell` measures `main`'s content box, and `useContentUp` answers as `useMediaQuery(theme.breakpoints.up(key))` would, against that width. `Grid` still lays the cards out; only the twelfths it's given change:

```tsx
import Grid from '@mui/material/Grid';
import { useContentUp } from 'src/components/contentWidth';

const across = useContentUp('md');

<Grid container spacing={2}>
  <Grid size={across ? 4 : 12}>…</Grid>
  <Grid size={across ? 8 : 12}>…</Grid>
</Grid>
```

Reach for it when a page's columns would crowd beside docked panels; otherwise size `Grid` by breakpoint (Rules → Content and layout). Outside `AppShell`, `useContentUp` reads the window. `useContentWidth` is the measuring half, for a frame that isn't `AppShell`: pass its `measure` as the element's `ref` and wrap the pages in its `provide`.

## Variants

- **With a panel:** a section with pages. Rows show an icon and a label, and optionally a second line (the item's type) or a count (open issues). The panel is MUI's `dense` list: rows have 4px of vertical padding and `body2` text, compact for a sidebar. The phone menu keeps full-height rows, for touch.
- **Filter:** a panel's `filter` adds a filter button to its header, whose menu narrows the pages to one `kind`: Workspace filters its items by type (Dashboards, Reports, Plans). A dot on the button shows a filter is on, and the button's name says which.
- **No panel:** leave a section's `panel` out when it has no pages of its own. Hovering it shows its tooltip, not a panel.
- **Missing:** `missing: true` marks a section the account doesn't have but can upgrade to. It shows one circled plus in the disabled color in place of its icon, quieter than the sections the account has, with its name as its tooltip, no badge and no panel; choosing it calls `onSectionChange`, so the app opens its upgrade page. To hide a Missing section (when the person has chosen to), leave it out of `sections`.
- **Header action:** a panel's `headerAction` adds one icon button to its header, before Collapse navigation, for a section-wide action: Notifications' preferences. It's left out of the phone menu, so put the same action in the page too.
- **At the end of the rail:** `placement: 'end'` puts a section at the bottom of the rail. Notifications is one: a section like any other, with its unread `count` and a panel that groups notifications by kind (All unread, Insights, Activity, Property alerts, Data alerts, App updates).
- **My account:** the signed-in person's section, at the very bottom with `placement: 'end'` and their `initials` on an avatar in place of an icon. Its panel lists the account pages (Profile, Preferences, Notification preferences, Modules and entitlements, Help and support), and `colorScheme: true` adds the appearance control under them: System, Light and Dark as icons (a monitor, a sun and a moon), each named in a tooltip. The light/dark switch lives there, not in the rail.
- **Companies:** pass every company the person belongs to as `companies` (the current one included), each with an optional `detail` such as their role and an optional `logo`. The company button always opens the company menu, with each company's mark and the current one checked; choosing another calls `onCompanyChange`. A mark is the company's `logo` on a white tile (marks are drawn for white), or its initials without one. With `onAddCompany`, an Add company row ends the menu, after a divider.
- **With an aside:** pass `aside` and `asideOpen`, and a button in `headerEnd` that toggles it. The column's width starts at `defaultAsideWidth` (344px) and `onAsideWidthChange` lets the app remember it. At 900px with the panel and the aside both docked at their default widths, the page is left about 220px: collapsing the panel or floating the aside gives it back, and a page can size its columns by that width (Usage → Columns by the page's width).
- **Floating aside:** `asideDocked={false}` floats the aside over the page at the bottom right, at its column's width and up to 640px tall, on level1 with the divider and a shadow. Mark its header with `data-drag-handle`: a press there, away from its buttons, drags it, kept 8px inside the window, and a double-click puts it back in the corner. `defaultAsidePosition` and `onAsidePositionChange` (its distance from the window's right and bottom edges, or `null` for the corner) let the app remember where it was left. Put the Dock and Undock control in the aside's own header and pass the choice back as `asideDocked`.
- **No header:** `hideHeader` leaves the header out on wide screens, for a page about making something new rather than a scope. Phones keep theirs, which holds the menu button.

### Phones

A phone's browser keeps its own toolbars on screen: Safari's sits at the bottom by default (iOS 26), Chrome's at the top. So below `md` the shell puts nothing at the bottom of the page and lets the browser's toolbars shrink:

- **The document scrolls** under a sticky header, rather than inside a fixed frame, so the browser can shrink its toolbars as people scroll. A `PageHeader` pins under that header.
- **Header:** the menu button (with a dot for unread notifications), `headerStart` (the scope) filling the header between it and `headerEnd`, and `headerEnd` (an icon button; there's no room for a label). The scope stays in view as the page scrolls. There's no page title: the menu opens on the current section's pages, and each page names itself in its own header. Where scope doesn't apply, leave `headerStart` empty and the header's middle stays empty.
- **Menu:** one column, not the rail and panel side by side. It opens on the current section's pages, with All sections to go up a level; there, Notifications leads, and sections with pages drill in. The menu's header (the back arrow, the level's title, Search and the close button) stays put while the list slides: in from the right when drilling in, from the left when going back, over 300ms (`duration.standard`, `easeOut`).
- **Pinned to the foot of the menu,** on both levels: My account, which drills into its pages and the appearance control, and the company button, an outlined button with the company's mark and name that opens the company menu, whatever the count. Choosing a company closes both menus, then calls `onCompanyChange`; so does Add company, then calls `onAddCompany`.
- **Header gutter:** the header takes the page's 16px inset, and the menu and page-action buttons at either end overhang it by their own 8px, so their glyphs sit on the content's edge.
- **Back closes it.** The menu and the company menu each take a step in the browser's history while open, so the browser's Back button or back swipe closes the top one rather than leaving the page.
- **Left out on phones:** sections with `hideOnPhone`, the panel's `filter`, `actions` and `headerAction` (put a section's New action, filters and settings in its page too), docking, resizing, the floating aside, hover and tooltips.
- **Safe areas:** `main`, the menu and the sheets pad by `env(safe-area-inset-bottom)`, which needs `viewport-fit=cover` in the app's viewport meta tag; without it the inset is 0.
- **Heights** use `dvh`, which follows the browser's toolbars as they show and hide. Menus and sheets use `overscroll-behavior: contain`, so scrolling to their end doesn't scroll the page behind.

Test the phone layout on a real iPhone (with Safari's toolbar at the bottom and at the top) and an Android phone: an emulator doesn't show how the browser's toolbars and back gesture behave.

## States

- **Panel undocked:** the page takes the room, and the header shows no panel buttons. Resting on a section in the rail for 80ms floats its panel over the page (once one is open, the next follows the pointer at once), 8px inside the frame on every edge (the frame's border included), at the docked panel's width less that 8px, so it follows the docked panel when it's resized. Its corners are concentric with the frame's (the frame's 16px is the panel's 8px theme radius plus the 8px gap), and it sits on level2 with a low shadow (`elevation={2}`). It stays while the pointer is over the rail or the panel (with a 200ms grace for crossing the gap), and closes when a page is chosen, the pointer leaves, or on Escape. Rail items with a panel show it in place of their tooltip. Clicking the current section's rail item (or Enter on it) pins its panel open, with focus inside, until a click outside, Escape or the rail item again closes it: the way to the panel and Dock navigation without hover. The panel's header has Dock navigation.
- **Docking:** Dock navigation in the floating panel carries the panel over rather than swapping it: it grows from where it floated into the docked slot (its position, size, corners, surface from level2 to level1 and shadow together, over `duration.standard` with `easeInOut`) while the slot opens from nothing and pushes the page over, so the page is laid out for the docked panel by the time the panel is there. It then holds until `loading` is `false`, so the page behind never shows mid-load, and fades out (`duration.shorter`). Docking another section's panel goes to that section (`onSectionChange`). Under reduced motion it docks at once.
- **Searching:** the dialog opens with the field focused and says what it finds as you type ("3 pages", or that none match); each result names its section. Choosing one closes the dialog and goes to the page; so does Escape, the close button and the browser's Back, without going anywhere.
- **Filtered:** only the pages of the chosen `kind` show, the filter button carries a dot, and the panel says when none match.
- **Section with news:** a section's `badge` puts a dot on its icon and is read with its label. With a `count`, the icon shows the number instead of the dot; give `badge` the words for it ("10 unread"). A Missing section takes no badge.
- **Aside floating:** it sits 16px from the window's right and bottom edges until it's dragged, stays in its corner as the window resizes (clamped 8px inside it), and raises its shadow while it's dragged.
- **Menu open on a phone:** the menu opens at the current section's pages; choosing a page closes it, and so do the close button, the scrim, Escape and the browser's Back.

## Do and don't

- Do keep one shell at the root, so the rail, panel and header stay put as pages change.
- Don't render a page's own frame, border or background inside `main`; the shell's frame is the page's edge (Rules → One border per edge).
- Do keep sections to a handful of top-level areas, each with an icon and a short label.
- Don't put page actions in the panel; put them in the page's header, and keep the panel for navigation.
- Do keep the header to the scope and page-wide actions.
- Don't put navigation controls (Dock navigation, Search) in the header; Dock navigation belongs to the panel, which can be opened from the rail without hover, and Search to the rail.
- Do leave a Missing section out of `sections` when the person has hidden it.
- Don't mark a Missing section with a badge or a section icon; the plus says what it is.
- Do give a section's `badge` words, since the dot alone is only color.
- Don't pass `fill` to rail or panel icons; selected rows fill theirs through the theme.
- Do mark sections people rarely need on a phone with `hideOnPhone`, so the phone menu stays short.
- Don't pin anything to the bottom of the page on phones; Safari keeps its toolbar there.

## MUI departures

- `paper-surface-levels`: the drawers, the floating panel, the menus and the header take their surface from their elevation: the floating panel is on level2, the company menu on the menu surface (level3), the phone menu on level4, and the header is transparent, on the frame's level1 (on phones, set to level1 so the page scrolls under it). In the dark scheme the menus, the phone menu, the bottom sheet and the search dialog sit on level1 with the divider as their edge, the frame's own surface. The floating aside is `elevation={0}` (level1) with the divider and a shadow in both schemes, the docked column's surface lifted off the page.
- `soft-shadow`: not used by the shell; its floating layers keep `theme.shadows`. A composer in the aside takes a raised surface framed in the `divider`, with no shadow.
- `selected-fills-icons`: the current section and page show their icons filled.
- `icon-button-radius`: the rail's and header's icon buttons round at the theme radius.
- `icons`: every icon is a Material Symbol through `Icon`.
- `medium-size`: icon buttons, toggle buttons and the search field stay at medium.
- `control-outlines`: the search dialog's field, the appearance control and the phone menu's company button are outlined in the control color.
- `toggle-button-text`: the appearance control's unselected options use secondary text.
- `button-text-case`: the phone menu's company button is written as the company's name, in Title Case.
- `button-text-weight`: the company button's label is at regular weight.
- `tabular-numerals`: a section's `count` badge, such as unread notifications, uses tabular figures.
- `focus-ring`: keyboard focus is a 2px ring in `palette.control.focus`, the brand blue (brand 700 in light, brand 200 in dark), 2px outside the control, instead of MUI's background tint alone.

Theme-wide departures (surfaces, borders, radius, type, reduced motion) apply too; see Foundations → MUI departures. With reduced motion on, the phone menu's slide finishes at once.

## Accessibility

- Landmarks: the rail is a `nav` named Main, the panel a `nav` named after its section, the page is `main` (`id="main"`) and the aside an `aside` named by `asideLabel`. On phones the menu is a dialog and a `nav`, both named Menu.
- A Skip to Content link is the first thing in the tab order and appears on focus.
- The current section and page carry `aria-current="page"`.
- Every icon-only button has an accessible name and a tooltip: sections by label, with their `badge` words ("Notifications, 10 unread"); on phones the menu button includes them too ("Open menu, 10 unread").
- The company button is named "Switch company: {name}" and says it opens a menu (`aria-haspopup`, `aria-expanded`). The company menu is named Switch company; its companies are radio items (`menuitemradio`), and the current one is `aria-checked`. Marks are decorative; Add company is a plain menu item.
- Search in the rail is named Search, says it opens a dialog, and has its tooltip. A Missing section's tooltip is its name, and its accessible name adds that it opens the upgrade page ("Maintenance. Opens the upgrade page").
- The appearance control is a `ToggleButtonGroup` labelled Appearance; each icon button is named System, Light or Dark (with a matching tooltip), and the chosen one is `aria-pressed`.
- The search dialog is named Search and opens with its field focused; its result count or no-match message is a polite `status`, and MUI's `Dialog` traps focus and closes on Escape. The filter button says it opens a menu, and its options are radio items (`menuitemradio`) with the chosen one `aria-checked`.
- The resize handles (the panel's and the aside's) are focusable `separator`s with their width as their value: the arrow keys move the edge by 8px, Home and End to its limits. Hovered, focused or dragged, each takes the primary color, softened toward both ends, so where to grab shows without relying on the cursor alone.
- The floating aside is an `aside` named by `asideLabel`. It moves only by pointer; keyboard users dock it instead, so put the Dock control, with an accessible name, in its header.
- MUI's `Drawer` and `Menu` trap focus while open and close on Escape.
- The floating panel opens on hover, and from the keyboard (or by touch) when the current section's rail item is chosen: it opens pinned, moves focus to its first control, and closes on Escape, handing focus back to the rail item. Its header holds Dock navigation, so docking doesn't need hover. The docking animation's overlay is hidden from screen readers and takes no pointer events; the docked panel under it is the live one.
