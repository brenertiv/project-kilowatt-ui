# Heatmap

A heatmap shows a value for every pair of two dimensions at once: each building's energy use by month, against last year or in total. `Heatmap` is Kilowatt's reference implementation: amCharts 5 (`@amcharts/amcharts5`) run through `useChart`, so it takes the chart theme for the active color scheme (Rules → Charts), inside MUI's `Card` (Material UI v9). Enertiv's app rebuilds its heatmaps from this one rather than importing it.

<Canvas of={HeatmapStories.Diverging} />

## When to use

- Use a heatmap to spot patterns across many rows and periods: which buildings ran over last year, and in which months.
- For one row over time, use a line chart; for a few rows, a line chart with a line each.
- For exact values people compare closely, use a table; a heatmap shows the pattern, its tooltips the numbers.
- For more rows than fit (dozens of buildings), page or filter them; don't shrink the rows.

## Usage

```tsx
import Card from '@mui/material/Card';
import CardHeader from '@mui/material/CardHeader';
import { Heatmap } from 'src/charts/Heatmap';

<Card variant="outlined">
  <CardHeader title="Energy Use Against Last Year" />
  <Heatmap
    rows={buildingNames}
    columns={['Jan', 'Feb', 'Mar']}
    cells={[{ row: '350 Park Avenue', column: 'Jan', value: -4.2 }, { row: '120 Wall Street', column: 'Jan', state: 'noData' }]}
    unit="%"
    cap={15}
    sides={['Less than 2025', 'More than 2025']}
    summary="Most buildings used less energy than in 2025; 425 Park Avenue used 18% more in July."
  />
</Card>
```

Each cell names its `row` and `column`. Every cell is one end color over the card at an opacity of its value: its distance from 0 against `cap`, full from the cap on and fading to the bare card at no change. A diverging heatmap colors the worse side of 0 in `error` and the better side in `chart.neutral`; set which side is worse with `worse`, or `worse="none"` where neither is (Rules → Charts → Deviation from a midpoint). A cell with no value says why with `state`: `'noData'` for nothing recorded (before metering began, a gap) and `'pending'` while it loads. A row and column with no cell at all show as no data. Keep `cells` stable (a constant or `useMemo`), since the chart is rebuilt when it changes.

## Variants

- **Diverging.** The default: a deviation from 0, the worse side in `error` and the better side in `chart.neutral`, each cell at an opacity of its distance from 0 over `cap`, full from the cap on, and 0 the bare card. Above 0 is worse by default, for a variance where less is better (energy, cost, emissions). Name both sides with `sides`; the legend draws the two ends meeting at the card, with the cap at each end.

<Canvas of={HeatmapStories.WorseBelow} />

- **Worse below.** `worse="below"`, for a variance where more is better (occupancy, data coverage): `error` under 0 and `chart.neutral` over it.

<Canvas of={HeatmapStories.Comparison} />

- **Comparison.** `worse="none"`, for a change where neither side is worse (this month against the same month a year earlier, weather against last year): `chart.diverging`, brand blue below 0 and parchment above, two hues that show direction without reading as a health status.
- **Sequential.** `scale="sequential"`: a magnitude, `chart.sequential[3]` at an opacity of each cell's place between the lowest and highest value, with the range at the legend's ends.

## States

- **No data.** The cell is hatched in `border.level3`, and its tooltip says "No data". It isn't filled, so it never reads as 0, which is the bare card.
- **Pending.** The same, with "Loading" in the tooltip, while that cell's data is on its way; the rest show as they arrive.

## Do and don't

- Do set `cap` to the change that matters (15%), so a few outliers don't wash out every other cell.
- Don't let one extreme month set the scale for the whole grid.
- Do say which side is worse with `worse`, or `worse="none"` where neither is, and say what each side means in `sides`.
- Don't put `error` on a comparison where neither side is worse (weather against last year); use `worse="none"`, so neither side reads as a status.
- Don't color the better side `success`: only the worse side signals, so the cells that need attention are the only ones in color.
- Don't color a magnitude with a deviation's colors; use `scale="sequential"`.
- Do give months before metering began `state: 'noData'`.
- Don't write 0 for a month with no data; 0 is a value, and it reads as "no change".
- Do write `summary` with the pattern and the cells that stand out.

## MUI departures

- `chart-palette`: a sequential heatmap takes `chart.sequential[3]`, the better side of a deviation `chart.neutral`, and a comparison (`worse="none"`) `chart.diverging`.
- `intents-on-surfaces`: a deviation takes `error` as it is on the card surface, at an opacity of each cell's value, for the worse side.

Theme-wide departures (the surface levels the card sits on, the theme radius) apply too; see Foundations → MUI departures.

## amCharts departures

How this chart differs from stock amCharts 5, from `src/charts/departures.ts`; Foundations → amCharts departures has the reasons.

- `chart-colors`: the chart's chrome takes the palette's roles.
- `chart-type`: labels are in the theme's font at the `caption` size, in `text.secondary`.
- `chart-tooltips`: tooltips sit on the menu surface with `text.primary`, outlined and rounded like a menu.
- `reduced-motion`: the chart animates only when the user hasn't asked for reduced motion.
- `chart-card`: the heatmap sits straight in an outlined `Card` under a title-only `CardHeader` and pads itself 16px (`inset`).
- `full-value-tooltips`: every cell has a tooltip with its row, column and full value and unit, signed for a change.
- `chart-text-alternative`: the `figure` around the heatmap is named by `summary` (`aria-label`).
- `heatmap-scale`: every cell one end color over the card at an opacity of its value over its cap or range, continuous: a deviation in `error` and `chart.neutral`, a comparison in `chart.diverging`, a magnitude in `chart.sequential[3]`; no data hatched; a gradient legend with the cap or range at its ends.

## Accessibility

- The heatmap draws on a canvas, so the `figure` around it is named by `summary` through `aria-label`. Say the overall pattern and the cells that stand out.
- Every cell's tooltip names its row and column and gives the full value, signed for a change ("+18%"), or why it has none.
- The legend under the grid names its ends in text: what each side means, the cap or the range, and what the hatched no-data cell stands for. The gradient between them is decorative.
- Only the worse side of a deviation is red, and the better side is the neutral; the two ends of a comparison are blue and parchment. Each pair stays apart under simulated color-vision deficiencies, and every cell's tooltip still gives its signed value.
- For the full table of values, offer it beside the heatmap (a table view).
