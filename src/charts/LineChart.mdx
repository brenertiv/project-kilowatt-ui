# Line chart

A line chart shows how values change over time. `LineChart` is Kilowatt's reference implementation: amCharts 5 (`@amcharts/amcharts5`) run through `useChart`, so it takes the chart theme for the active color scheme (Rules → Charts). Enertiv's app rebuilds its charts from this one rather than importing it.

<Canvas of={LineChartStories.Highlight} />

## When to use

- Use a line chart for a measure over time: daily energy use, demand through a day, monthly cost.
- For values across categories that aren't time (buildings, utilities), use a column chart.
- For parts of one whole, with six parts or fewer, use a donut chart.
- For more than six lines, group the smallest into "Other", split the chart, or show a table.
- For a measure against what drives it in another unit (energy against outdoor temperature), use two units on two value axes. Past two units, split into separate charts.

## Usage

```tsx
import Card from '@mui/material/Card';
import CardHeader from '@mui/material/CardHeader';
import { LineChart } from 'src/charts/LineChart';

const series = [
  { field: 'current', name: 'This period' },
  { field: 'previous', name: 'Previous 30 days', neutral: true, dashed: true },
];

<Card variant="outlined">
  <CardHeader title="Energy Use" />
  <LineChart data={readings} series={series} unit="kWh" summary="This period used 34,024 kWh, 5% less than the previous 30 days." />
</Card>
```

The value axis sits on the right. For a second unit, mark its lines `right` and set `rightUnit`: the first unit's axis moves to the left, and the chart adds a right value axis with the second unit above it, on the left axis's gridlines, and every line's legend name and tooltip carry its unit:

```tsx
const series = [
  { field: 'current', name: 'Energy use' },
  { field: 'temperature', name: 'Outdoor temperature', neutral: true, right: true },
];

<LineChart data={readings} series={series} unit="kWh" rightUnit="°F" summary="…" />
```

`data` is rows of numbers with a UTC timestamp in `date`. Keep `data`, `series`, `references` and `ranges` stable (constants or `useMemo`), since the chart is rebuilt when they change.

Targets, marked stretches of time, projections and scores read against bands:

```tsx
import { scoreBands } from 'src/charts/meanings';

// A target or benchmark: a dashed line labeled with its name and full value.
<LineChart data={readings} series={series} unit="kWh" references={[{ value: 1100, label: 'Daily target' }]} summary="…" />

// A stretch of time: a band in action.hover, named inside at the top right.
<LineChart data={readings} series={series} unit="kWh" ranges={[{ from: Date.UTC(2026, 8, 14), to: Date.UTC(2026, 8, 18), label: 'High night load' }]} summary="…" />

// Measured, then projected: one line, dashed from the first projected month.
<LineChart data={emissions} series={[{ field: 'emissions', name: 'Emissions', projectedFrom: Date.UTC(2026, 10, 1) }]} unit="tCO₂e" interval="month" summary="…" />

// A score in its bands, with today's score marked.
<LineChart data={scores} series={[{ field: 'score', name: 'Maintenance score', bands: scoreBands, markers: 'last' }]} unit="pts" summary="…" />
```

Product meanings take their color from `src/charts/meanings`: spread `meaningColor(utilitySlots, 'Natural Gas')` into a line for its slot. Look meanings up by the API's name, never a translated label.

## Variants

- **Single.** One measure; the line takes the first series color.
- **Highlight.** The line that matters in a series color, and the context (the previous period, a baseline) with `neutral` and `dashed`.
- **Comparison.** Up to six lines, told apart by `chart.series` color in order. Give a line a `slot` when it stands for a fixed meaning (a utility type), so it keeps one color on every chart.
- **Aligned with content.** A chart under a `CardContent` (a headline number): its default 16px inset lines it up with the content above.
- **Two units.** A measure on the left axis and what it's read against on the right (`right`, `rightUnit`), each axis labeled with its unit. Draw the context line `neutral`.
- **Target.** A goal or benchmark the line is read against: `references`, a dashed line in `text.secondary` labeled with its name and full value inside the plot. Set `labelBelow` on a reference whose label would cover the data just above its line.
- **Time ranges.** A stretch of time the line is read in, such as the window a finding is about: `ranges`, a band in `action.hover` behind the lines (Rules → Charts), named inside at the top right in `text.secondary`. A name wider than its band runs left over the plot.
- **Projected.** One line measured up to a date and projected after it: `projectedFrom` continues the line dashed in its own hue, and the tooltip says "projected". For a stretch that's provisional rather than projected (a month still being billed), set `projectedNote` to what the tooltip should say instead: `incomplete`.
- **Score bands.** A score colored by status, band by band (`bands`, usually `scoreBands`), with the band named in the tooltip; `markers: 'last'` marks the latest reading. A chart colored by status has no other colored line. Set `max={100}` for a score or a percentage, so the axis always runs to the ceiling.
- **Pathways.** Scenarios years ahead against a pathway (`interval="year"`): each scenario in a series color, the pathway `neutral`. Keep to one neutral line, so the legend tells every line apart. Rows can also be a `quarter` apart.

`dashed` marks a variant of another line, such as the previous period; it keeps the hue rather than taking a new color. `markers: 'all'` marks every point of sparse data, where each point is a reading.

## Do and don't

- Do put the chart in an outlined `Card` (`variant="outlined"`) under a title-only `CardHeader` that says what's measured, straight in the `Card` with no `CardContent`: the chart pads itself through `inset`, 16px by default to line up with the title and any `CardContent`, `1` (8px) for a tighter fit, `0` to run edge to edge. The page sets the period.
- Don't put the unit in the card header or a subtitle; `unit` shows it above the value axis and in the tooltip, next to the numbers.
- Do write `summary` as one sentence with the numbers that matter.
- Don't leave the summary generic ("Energy use chart"); it's what screen readers say for the whole chart.
- Do draw the context line `neutral` when one line is the point.
- Don't give a baseline its own series color; two colored lines read as equals.
- Do give a line a `slot` when it stands for a product meaning, so electricity is the same color on every chart.
- Don't set a color in chart code or add a palette color for a meaning; map the meaning to a slot.
- Do use `rightUnit` for a second unit, and draw the line that's context `neutral`.
- Don't put a third unit on a chart, or two scales of one quantity (kW and MW); split the chart or convert to one unit.
- Do draw a forecast with `projectedFrom` on the line it continues.
- Don't draw a forecast as a second series in a second color; a variant keeps its hue.
- Do read a score against `scoreBands`, so every score chart bands alike.
- Don't color a score by status and add another colored line; color a chart by series or by status.
- Do group or switch to a table past six lines.
- Don't show more than six colored lines; the hues stop being told apart.

## MUI departures

- `chart-palette`: lines take `chart.series` in order or by `slot`, and neutral lines take `chart.neutral`.
- `intents-on-surfaces`: a line in `bands` takes the intents (`success`, `info`, `warning`, `error`) as they are on the card surface.

Theme-wide departures (the surface levels the card sits on, the theme radius) apply too; see Foundations → MUI departures.

## amCharts departures

How this chart differs from stock amCharts 5, from `src/charts/departures.ts`; Foundations → amCharts departures has the reasons.

- `chart-colors`: the chart's chrome takes the palette's roles, and series take `chart.series` in order, used as they are.
- `chart-type`: labels are in the theme's font at the `caption` size, in `text.secondary`.
- `chart-gridlines`: gridlines are full strength in `border.level2`, a step past the divider, so they read on the card.
- `chart-tooltips`: tooltips sit on the menu surface with `text.primary`, outlined and rounded like a menu.
- `value-axis-labels`: value-axis numbers are left-aligned, 8px from the plot, so a left axis lines up with the card's title.
- `legend-items`: legend items have no left padding, so the legend lines up with the axis and the title.
- `compact-axis-numbers`: axis numbers are compact in the viewer's locale (1.5K, 60K).
- `reduced-motion`: the chart animates only when the user hasn't asked for reduced motion.
- `chart-card`: the chart sits straight in an outlined `Card` under a title-only `CardHeader` and pads itself 16px (`inset`).
- `value-axis-side`: one value axis sits on the right; two units take the left and the right.
- `axis-units`: each value axis has its unit above it, left-aligned with its numbers (`axisUnit`).
- `full-value-tooltips`: every hoverable item has a tooltip with its exact value and unit (`tooltipNumberFormat`).
- `chart-text-alternative`: the `figure` around the chart is named by `summary` (`aria-label`).
- `legend-layout`: the legend sits below the plot in up to three columns, for two or more series.
- `reference-lines`: `references` are dashed `text.secondary` lines, labeled with name, full value and unit inside the plot on the card surface.
- `projected-segments`: `projectedFrom` continues a line dashed in its own hue, with "projected" in the tooltip.
- `status-bands`: `bands` color a line and its markers by intent, band by band, and name the band in the tooltip.
- `point-markers`: no markers by default; `markers` marks the last point or every point with a 4px dot ringed in the card surface.

## Accessibility

- Every point, column or slice shows its exact value and unit in a tooltip on hover, since axis numbers are rounded to compact form (1.5K).
- The chart draws on a canvas, so the `figure` around it is named by `summary` through `aria-label`. The summary isn't shown on screen; it's the chart's text alternative.
- amCharts adds keyboard focus and screen-reader announcements for the legend and data points.
- Lines are told apart by color and by name in the legend and tooltip; a dashed line is told apart by pattern too.
- A projected stretch is dashed and its tooltip says "projected"; a banded score's tooltip names its band; a reference line and a time range are labeled in text. None of them rests on color alone. Say the target, the range, the projection or the band in `summary` when it matters.
- With two units, each legend name carries its unit ("Energy use (kWh)"), so which axis a line reads against doesn't depend on color. Say both units in `summary`.
- For detailed values, offer the data as a table beside the chart.
