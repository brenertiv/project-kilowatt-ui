# Forms

Value pickers are MUI components from `@mui/material`, used as MUI documents them and themed as stock MUI. There are no wrapper components. For a plain text input, see Primitives/Field. Don't pass colors; the default `primary` color is the selected state.

## Which picker

| The user is choosing | Use |
| --- | --- |
| One of a short, known list (under about ten) | Select |
| One of a long list, found by typing | Autocomplete |
| An exact number within limits | Number field |
| An approximate value in a range | Slider |
| One (or several) of a few short options, such as units | Toggle button group |
| One of a few options that should all stay visible | Radio group |

## Select

`TextField` with `select` and a `MenuItem` per option. `TextField` supplies the label and outline, so the select matches the other fields.

```tsx
<TextField select label="Building" value={building} onChange={(event) => setBuilding(event.target.value)}>
  {buildings.map((item) => (
    <MenuItem key={item.value} value={item.value}>{item.label}</MenuItem>
  ))}
</TextField>
```

## Autocomplete

A searchable list, in place of a combobox. Pass `options`, render the input as a `TextField` with a `label`, and set `noOptionsText` to say what was not found. When options are objects, set `isOptionEqualToValue`.

```tsx
<Autocomplete
  options={meters}
  value={meter}
  onChange={(_event, next) => setMeter(next)}
  isOptionEqualToValue={(option, value) => option.value === value.value}
  noOptionsText="No meters found."
  renderInput={(params) => <TextField {...params} label="Meter" />}
/>
```

## Number field

`TextField` with `type="number"`, and `min`, `max` and `step` on the input through `slotProps.htmlInput`. Put the unit in the label and the limits in `helperText`. MUI has no stepper field of its own; the browser's number input supplies arrow-key stepping.

## Slider

`Slider` with `aria-labelledby` pointing at a visible label, and the current value shown beside it. Set `getAriaValueText` and `valueLabelFormat` so the value reads with its unit.

## Toggle button group

`ToggleButtonGroup` of `ToggleButton` with an `aria-label`. Set `exclusive` for one choice; MUI passes `null` when the selected button is pressed again, so ignore that to keep one selected. Leave `exclusive` off to allow several. Use `size="small"` in toolbars and card headers.

## Radio group

`FormControl` holding a `FormLabel` with an `id`, then a `RadioGroup` with `aria-labelledby` and a `FormControlLabel` per `Radio`. Set `disabled` on the `FormControl` to turn off the whole group.

## Do and don't

- Do give every picker a visible label.
- Do write option labels in sentence case, and units as they are written ("kWh", "therms").
- Don't use a select for more than about ten options; use an autocomplete.
- Don't use a slider when the exact number matters; use a number field.

## Accessibility

- `TextField` (also for select and number) and Autocomplete's input wire their label to the control.
- Autocomplete implements the combobox pattern with arrow keys, Enter and Escape.
- Slider and radio group take their name from the label they point at with `aria-labelledby`; the toggle group from its `aria-label`.
