# Overlays

Floating content built from Base UI parts and `ui-*` classes in `src/styles.css`. There are no wrapper components: copy the markup from the story's code panel. Every overlay renders in its part's `Portal`, and anchored ones put `ui-positioner` on the positioner (it sets the stacking order). In light mode popups, tooltips and toasts carry the md shadow and dialogs the lg shadow (dark mode uses a 1px ring); all fade and scale in over 150ms unless reduced motion is on.

## Menu

A list of actions behind one button. `Menu.Trigger` is a `ui-btn`; then `ui-positioner`, `ui-popup` on `Menu.Popup`, `ui-item` on each `Menu.Item`, and `ui-separator` before a destructive or rare action. A `ui-item` with `data-destructive` shows in the error color.

<Canvas of={OverlaysStories.MenuRecipe} />

## Tooltip

A short, non-essential hint on hover or focus: `ui-tooltip` on `Tooltip.Popup`. The app's providers already include `Tooltip.Provider`. Never put the only copy of important information in a tooltip.

<Canvas of={OverlaysStories.TooltipRecipe} />

## Popover

Extra detail the user opens on click and can interact with: `ui-popup ui-popup-padded` on `Popover.Popup`, with `Popover.Arrow` (`ui-arrow`), `Popover.Title` (`ui-popup-title`) and `Popover.Description` (`ui-description`).

<Canvas of={OverlaysStories.PopoverRecipe} />

## Dialog

A focused task that blocks the page until done or cancelled. `Dialog.Backdrop` gets `ui-backdrop`, `Dialog.Viewport` gets `ui-dialog-viewport` (centers the dialog), `Dialog.Popup` gets `ui-dialog` (up to 420px wide), with `ui-dialog-title` and `ui-description`. End with a `ui-dialog-actions` row of `Dialog.Close` buttons: `ui-btn` to cancel, then `ui-btn ui-btn-solid` for the primary action.

<Canvas of={OverlaysStories.DialogRecipe} />

## Alert dialog

Confirming a destructive or irreversible action: `AlertDialog` with the same classes as a dialog. It does not close on an outside click, so the user must choose. Name the buttons by outcome ("Keep", "Delete").

<Canvas of={OverlaysStories.AlertDialogRecipe} />

## Toast

Brief confirmation that something happened in the background. Call `Toast.useToastManager().add()` with a `title`, `description` and `timeout`; the app's `ToastOutlet` (in `src/AppProviders.tsx`) renders it as a `ui-toast` with a dismiss button. Don't render `Toast.Root` yourself.

<Canvas of={OverlaysStories.ToastRecipe} />

## Do and don't

- Do use an alert dialog, not a dialog, for anything that cannot be undone.
- Do keep tooltip text short and repeat anything essential on the page.
- Don't put an action the user must take only in a toast; it times out.
- Don't leave off `ui-positioner` or the `Portal`; the overlay would render under the page.

## Accessibility

- Base UI traps focus in dialogs, returns focus to the trigger on close, closes on Escape, and wires the title and description as the dialog's name and description.
- Menus get arrow-key movement and type-ahead; tooltips open on keyboard focus as well as hover.
- The caller must give every dialog a `Title`, and name icon-only triggers with `aria-label`.
