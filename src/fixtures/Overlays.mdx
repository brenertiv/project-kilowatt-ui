# Overlays

Floating content is MUI components from `@mui/material`, used as MUI documents them and themed as stock MUI. There are no wrapper components. MUI renders every overlay in a portal with its own stacking order, so there is nothing to wrap or position by hand.

## Which overlay

- Menu: a list of actions behind one button.
- Tooltip: a short hint on hover or focus that the user can do without.
- Popover: extra detail the user opens on click and may interact with.
- Dialog: a focused task that blocks the page until done or cancelled.
- Alert dialog: confirming a destructive or irreversible action.
- Snackbar: brief confirmation that something happened in the background.

## Menu

A `Button` that opens a `Menu` anchored to it, with `aria-controls`, `aria-haspopup` and `aria-expanded` on the button and `aria-labelledby` on the list, as in MUI's docs. Put a `Divider` before a destructive or rare action, and confirm a destructive one in an alert dialog rather than coloring the item.

## Tooltip

Wrap the element in `Tooltip` with a `title`. By default MUI makes the title the child's accessible name, which suits an icon button; when the child already has a visible label, set `describeChild` so the title becomes its description instead. The child must be able to hold a ref and take focus, such as a `Button` or `IconButton`; wrap a disabled button in a `span`. Use it to name an icon button's action or to add a value the page already shows elsewhere.

## Popover

A `Popover` anchored to the button that opened it, with padding, a `Typography` title and secondary text. Use a menu instead when the content is a list of actions.

## Dialog

`Dialog` with `DialogTitle`, `DialogContent` and `DialogActions`, and `aria-labelledby` and `aria-describedby` pointing at the title and description. End with a text Cancel button, then a contained button that names the action.

## Alert dialog

MUI has no separate alert dialog: use `Dialog` with `role="alertdialog"`, ignore the `backdropClick` close reason so the user must choose, and keep Escape as cancel. Put `autoFocus` on the safe button, and give the confirming one `color="error"`. Name the buttons by outcome ("Keep", "Delete").

<Canvas of={OverlaysStories.AlertDialogRecipe} />

## Snackbar

`Snackbar` with a `message`, an `autoHideDuration` and a dismiss `IconButton` (with `XIcon` from `src/icons` and an `aria-label`) as its `action`. Ignore the `clickaway` close reason so it is not dismissed by unrelated clicks. Show one at a time.

## Kilowatt rules

- Labels and titles are sentence case; icons come from `src/icons`.
- Don't pass colors to overlays; palette roles such as `color="error"` on a confirming button are fine.
- Popovers and menus keep MUI's default surface and elevation; don't restyle them.

## Do and don't

- Do use an alert dialog, not a dialog, for anything that cannot be undone.
- Do keep tooltip text short and repeat anything essential on the page.
- Don't put an action the user must take only in a snackbar; it times out.

## Accessibility

- MUI's `Dialog` traps focus, returns it to the trigger on close and closes on Escape; the caller wires the title and description.
- `Menu` gets arrow-key movement and type-ahead; `Tooltip` opens on keyboard focus as well as hover.
- MUI gives the snackbar content `role="alert"`, so screen readers announce it; keep it to one sentence.
