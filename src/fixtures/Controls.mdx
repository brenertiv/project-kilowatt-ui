# Controls

On/off and view-switching controls are MUI's `Switch`, `Checkbox` and `Tabs` from `@mui/material`, used as MUI documents them and themed as stock MUI. There are no wrapper components. Don't pass colors; the default `primary` color is the checked and selected state.

## Switch

A setting that takes effect at once, with no Save button. Put the `Switch` in the `control` of a `FormControlLabel`, which gives it its visible label.

```tsx
import FormControlLabel from '@mui/material/FormControlLabel';
import Switch from '@mui/material/Switch';

<FormControlLabel
  control={<Switch checked={alerts} onChange={(_event, checked) => setAlerts(checked)} />}
  label="Real-time alerts"
/>
```

## Checkbox

An option applied with the rest of a form, when a Save button commits it. Use `FormControlLabel` the same way. For a parent whose children are only partly checked, set `indeterminate` on the parent; checking it checks every child.

```tsx
import Checkbox from '@mui/material/Checkbox';
import FormControlLabel from '@mui/material/FormControlLabel';

<FormControlLabel
  control={<Checkbox checked={all} indeterminate={some && !all} onChange={toggleAll} />}
  label="All meters"
/>
```

## Tabs

Switching between views of one subject. Give `Tabs` an `aria-label`, give each `Tab` an `id` and `aria-controls`, and render each panel with `role="tabpanel"`, `aria-labelledby` and `hidden`, as in MUI's docs. Put a divider-colored bottom border under the list. When the tabs may not fit, as on a phone, set `variant="scrollable"` with `scrollButtons="auto"` and `allowScrollButtonsMobile`.

```tsx
import Tab from '@mui/material/Tab';
import Tabs from '@mui/material/Tabs';

<Tabs value={view} onChange={(_event, next) => setView(next)} aria-label="Building views" variant="scrollable" scrollButtons="auto">
  <Tab label="Usage" id="tab-usage" aria-controls="panel-usage" />
  <Tab label="Demand" id="tab-demand" aria-controls="panel-demand" />
</Tabs>
```

## Do and don't

- Do use a switch only when the change applies immediately; use a checkbox when a Save button applies it.
- Do label every switch and checkbox with `FormControlLabel`, so clicking the text toggles the control.
- Do write tab labels as one or two words in sentence case.
- Don't use tabs to move between different subjects; they switch views of one subject.

## Accessibility

- MUI renders a native checkbox input for `Switch` and `Checkbox`; `indeterminate` shows the mixed state on the parent.
- `Tabs` implements the tablist pattern with arrow-key movement; the caller wires each tab to its panel with `id`, `aria-controls` and `aria-labelledby`.
- The label text is the accessible name for switches and checkboxes; the caller must supply it.
